# tuisong-xiaohongshu

一个面向 [Agent Skills](https://agentskills.io) 的开源 Skill：持续跟踪指定
小红书创作者，只抓取首次建立基线之后出现的新笔记，根据用户提供的关键词筛选，
并将命中笔记的标题、发布时间和原文依据摘要发送到邮箱。

## 本次更新（2026-11-10）

### 发现的问题

原规则将“创作者名称 + 小红书号”都作为必填账号信息。但部分小红书创作者
主页不展示小红书号，导致用户即使提供完全一致的创作者名称，也无法按原规则
完成账号匹配和建立监控。

同时，如果对所有创作者一律只匹配名称，又可能把同名账号误判为同一人，
造成错抓或误推送。

### 本次修改

- 小红书号改为可选：创作者主页未显示时不再强制要求。
- 主页显示小红书号时，创作者名称和小红书号必须同时精确匹配。
- 主页未显示小红书号时，只按创作者名称精确匹配。
- 同名账号无法通过主页信息唯一识别时停止匹配，不猜测账号。
- 状态记录新增账号匹配模式 `name_and_id` / `name_only`。
- 作者未显示小红书号时，邮件中的创作者信息自动省略该字段。

### 解决的问题

- 修复了未展示小红书号的创作者无法建立监控的问题。
- 保留了展示小红书号时的双重校验，降低同名账号误匹配和错误推送风险。
- 明确区分两种账号匹配场景，避免后续巡检与邮件展示规则不一致。

## 1. 项目解决什么问题

手动刷新小红书创作者主页、筛选关键词、打开笔记、总结内容，再复制到邮件里，
步骤重复且容易漏掉更新。

本项目把这一流程整理成可复用的 Agent Skill：

- 不重新收集历史笔记，只比较当前笔记 ID 与已记录 ID。
- 只在标题、正文、图片文字、视频字幕或视频转写命中关键词时推送。
- 摘要严格来自抓取到的原文内容，不补充原文没有的信息。
- 首次运行只建立基线，不把账号原有笔记当成更新发送。
- 后续出现命中新笔记时，自动发送邮件。

本项目本身不是常驻服务，也不包含后台守护脚本。每次 Skill 调用完成一轮巡检；
需要持续监控时，请使用 Codex Automation、cron、Windows 任务计划程序或其他
调度器定期调用。

## 2. 主要功能

- **有条件账号识别**：创作者主页同时显示名称和小红书号时，两项都必须精确
  匹配；主页未显示小红书号时，仅按创作者名称精确匹配。同名账号无法唯一
  识别时会停止匹配，避免误推送。
- **增量巡检**：首次只保存当前可见笔记 ID；之后只处理新出现的笔记 ID。
- **关键词筛选**：支持“任一命中”和“全部命中”，默认是“任一命中”。
- **多类型内容读取**：仅对新增候选读取笔记详情，支持标题、正文、图片文字和
  视频字幕或转写中可获得的内容。
- **原文依据摘要**：生成 2–4 句或 3–5 条摘要，不添加原文未出现的观点、
  背景或结论。
- **邮件推送**：每条命中笔记发送一封邮件，包含标题、发布时间、命中关键词、
  内容类型、原文链接和摘要。
- **失败重试**：邮件发送失败的笔记保留在待重试队列，下一轮优先重试。
- **防存量误推**：不执行历史关键词搜索，不翻取旧笔记正文，不再次发送已成功
  推送的笔记。
- **凭据隔离**：邮箱客户端授权码不写入技能文件、README 或监控状态。

如果笔记详情的文本和视频转写都无法读取，则不会仅凭封面、音乐标题或评论
编造摘要。视频没有可读取字幕或转写时，邮件会明确标注限制。

## 3. 安装方法

### 3.1 前置条件

需要准备：

1. 支持 Agent Skills 的 Agent 客户端。
2. 已安装并登录的 [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)。
3. MCP 服务地址，默认是 `http://localhost:18060/mcp`。
4. 可用的邮件连接器，或支持 SMTP 的邮箱客户端授权码。
5. 若需要持续推送，还需要一个周期性调度器。

### 3.2 安装 Skill

将 `tuisong-xiaohongshu/` 整个目录放入目标 Agent 的 skills 目录。例如：

```bash
cp -r tuisong-xiaohongshu <你的 Agent skills 目录>/
```

目录结构应为：

```text
tuisong-xiaohongshu/
├── SKILL.md
└── agents/
    └── openai.yaml
```

安装后重启 Agent 会话，使 Skill 被重新加载。

### 3.3 配置小红书 MCP

先启动 `xiaohongshu-mcp`，确认本地地址可访问：

```text
http://localhost:18060/mcp
```

在 Codex 桌面端可通过：

```text
Settings → MCP servers → Add server
```

填写：

```text
名称：xiaohongshu
类型：Streamable HTTP
地址：http://localhost:18060/mcp
```

保存并重启 Codex。也可以在 `~/.codex/config.toml` 中加入：

```toml
[mcp_servers.xiaohongshu]
url = "http://localhost:18060/mcp"
```

重启后确认 `check_login_status` 等小红书 MCP 工具可用，并完成小红书登录。

### 3.4 配置邮箱授权码

不要把授权码直接写入项目文件。建议保存到当前用户的环境变量：

```powershell
[Environment]::SetEnvironmentVariable(
  "TUISONG_XHS_SMTP_AUTH_CODE",
  "你的邮箱客户端授权码",
  "User"
)
```

配置后重新启动 Agent。发送前仍需确认发件邮箱、SMTP 主机、端口和加密方式。

## 4. 使用方法

### 4.1 提供监控参数

在 Agent 中输入：

```text
使用 $tuisong-xiaohongshu 监控：
创作者：面包研究所
小红书号：123456789（主页未显示时可省略）
关键词：早餐, 发酵
匹配方式：任一
收件邮箱：you@example.com
发件邮箱：you@example.com
SMTP 服务器：smtp.example.com
SMTP 端口：465
加密方式：SSL
客户端授权码：已配置到 TUISONG_XHS_SMTP_AUTH_CODE
```

如果创作者主页不显示小红书号，可以省略该项，Skill 将只按创作者名称精确
匹配。如果主页显示小红书号，则创作者名称和小红书号必须同时匹配。

如果关键词缺失，Skill 会要求补充；不会从创作者历史笔记中自行猜测关键词。

### 4.2 首次运行

首次运行只读取当前可见笔记列表并保存笔记 ID，不读取这批存量笔记正文，也
不发送邮件。这样可以避免把账号原有内容误认为更新。

### 4.3 后续运行

每次调用执行一轮巡检：

1. 先重试上一轮发送失败的笔记。
2. 获取创作者当前可见笔记列表。
3. 找出不在已记录 ID 和待重试 ID 中的新候选。
4. 只读取新候选详情并执行关键词匹配。
5. 对命中笔记生成原文依据摘要并发送邮件。
6. 将已处理笔记加入已见列表；发送失败则加入待重试列表。

状态文件默认位于：

```text
${CODEX_HOME:-~/.codex}/state/tuisong-xiaohongshu/state.json
```

每个订阅按创作者名称、可选的小红书号、账号匹配模式、关键词、匹配方式和
收件邮箱隔离。状态中只保存笔记 ID、时间和发送状态，不保存邮箱授权码或
完整笔记正文。

### 4.4 持续监控

Skill 自身不常驻运行。建议通过 Codex Automation、cron 或 Windows 任务计划程序
每 15–60 分钟调用一次，运行频率应结合创作者发帖频率和账号限流情况调整。

```text
加密方式：SSL

```

### 首次运行输出

```text
已建立基线：记录 12 条当前笔记 ID，未读取存量正文，未发送邮件。
本轮统计：候选 0，命中 0，发送 0，待重试 0。
```

### 发现新笔记时的输出

```text
本轮统计：候选 2，命中 1，发送 1，待重试 0。
已向 you@example.com 发送“冬天做面包，我只用这一个发酵方法”的更新邮件。
```

### 邮件输出示例

```text
主题：[小红书更新] 冬天做面包，我只用这一个发酵方法 - 面包研究所

创作者：面包研究所（小红书号：123456789）
标题：冬天做面包，我只用这一个发酵方法
发布时间：2026-11-09 08:30

内容类型：视频

内容摘要：
- 视频介绍先将温水和面粉混合静置，再加入酵母继续揉面的做法。

- 视频以面团膨胀到原来两倍大小作为进入下一步的判断依据。
```

```text
本轮统计：候选 1，命中 0，发送 0，待重试 0。

```

### 邮件发送失败时的输出

```text
本轮统计：候选 1，命中 1，发送 0，待重试 1。
邮件发送失败，笔记已保留在待重试队列，下一轮将优先重试。
```

## 注意事项

- 摘要只来自笔记标题、正文、图片文字、视频字幕或视频转写。
- 不支持用 Playwright、WebFetch 等方式替代已登录的小红书 MCP。
- 小红书登录失效、MCP 不可用或笔记详情无法读取时，本轮不会编造内容。
- 修改创作者名称、小红书号、关键词、匹配方式或收件邮箱后，会按新的订阅
  组合重新建立基线。
- 邮件授权码建议使用环境变量或系统密钥存储，不要提交到 Git。
